# 海龟汤仙人 · 微信小程序版

从旧项目 `Turtle_Soup`（Flask 网页版）移植核心逻辑的微信小程序，基于**微信云开发**实现多人联机。
AI 主持人只回答「是 / 不是 / 不重要」，玩家推理真相、提交故事还原，猜对全员恭喜过关。

---

## 一、第一版功能

| 模块 | 说明 |
|---|---|
| 房间联机 | 填昵称创建房间 → 得 6 位纯数字房间码 → 朋友凭码加入；也可直接分享小程序卡片，好友点开自动填码 |
| AI 主持人 | DeepSeek 驱动，只答「是 / 不是 / 不重要」；支持「整理线索」；记住最近 20 轮对话 |
| 故事还原 | 提交你的真相推测 → AI 判定「还原正确 / 大致正确 / 错误」→ 猜对全员弹「恭喜过关」 |
| 玩家群聊 | 独立聊天频道（AI 不参与），@成员昵称高亮 |
| 在线成员 | 实时在线状态（60 秒无心跳视为离线，同旧版） |
| 题目管理 | 房主专属：内置题库选题、上传 JSON 题库（格式同旧版）、切换题目、揭晓答案 |
| 汤底保密 | 答案与胜利条件只存云端：汤底揭晓前任何玩家都拿不到，胜利条件始终不展示给玩家（比旧版更严格） |
| 内置题库 | `cloudfunctions/init/builtin.json` 里的经典海龟汤，开局自动随机一题（想加题就编辑这个文件后重新部署 init） |
| 定时清理 | 每天凌晨 3 点自动清空所有房间（同旧版），房间最长存活 24 小时 |

第二期已上线：**故事广场**（浏览/搜索/发布/编辑/删除/一键开局/加载进房间）。第三期规划：管理后台（房间/故事/公告）。

## 一·五、故事广场（第二期）

| 功能 | 说明 |
|---|---|
| 浏览 + 搜索 | 按名称/编号/汤面搜索，分页加载更多；"我的发布"页签 |
| 发布故事 | 在线填表，或从 JSON 文件填入；**支持批量：数组里有几道就发几道（一次最多 20 道）**，弹确认框后整批发布；过微信内容安全检测后直接发布 |
| 自动编号 | `#00065` 起原子自增（接续旧版计数），不重号；批量发布时一次性预取整批编号再并发写库 |
| 编辑 / 删除 | **仅发布者本人微信**可编辑/删除自己的故事（替代旧版"编号+密码"，更安全） |
| 一键开局 | 广场详情点"用这道题开局"→ 自动创建房间并加载该题 |
| 加载进房间 | 房主在房间题库弹窗的"故事广场"页签加载广场题 |
| 汤底保密 | 广场列表/详情只展示汤面；汤底仅发布者编辑时可见 |

**广场从 JSON 批量发布是怎么走的**（`cloudfunctions/plaza/index.js` 的 `publish`）：

1. **全量校验**：先检查每道题的名称/汤面/汤底/胜利条件，有一条不合格就整批不发布，一条都不写库。
2. **分组并发送检**：每组 5 题同时调 `msgSecCheck`，20 道题只需 4 轮往返。
3. **一次性预取编号 + 并发写库**：一次事务把这批的编号全占下来，再并发写入 `stories`，避免"每道题开一次事务"把云函数拖超时。

> ⚠️ `plaza` 云函数的超时时间是**控制台默认的 3 秒**（`room` 是 60 秒）。上面的分段设计是为了在 3 秒内也能跑完 10 道左右；如果你以后要一次发 20 道，建议到云开发控制台把 `plaza` 的超时也改成 60 秒：控制台 → 云函数 → `plaza` → 配置 → 超时时间。

> 报错对照：`cloud.callFunction:fail ... timed out after 3 seconds`（`-504003`）= 本批没跑完，已写入的题会留在广场（编号会有跳号），重新发之前先检查是否已部分入库。

**第二期部署增量**（已部署过第一期的看这里）：
1. 右键 `cloudfunctions/plaza` → 上传并部署
2. 右键 `cloudfunctions/room` → 重新上传并部署（加了广场联动）
3. 右键 `cloudfunctions/init` → 重新上传并部署，再"云端测试"运行一次（新建 `counters` 集合）
4. 数据库给 `counters` 集合设置安全规则 `{"read": false, "write": false}`（同 stories）

## 二、旧逻辑 → 新实现对照表

| 旧项目（Flask + Socket.IO） | 新项目（小程序 + 云开发） |
|---|---|
| 内存房间字典 `rooms` | 数据库 `rooms` 集合（文档 `_id` = 房间码） |
| Socket.IO 实时推送 | 数据库实时推送 `watch`（消息/群聊/房间状态三路监听） |
| HTTP 心跳接口 | `room` 云函数 `heartbeat`，小程序每 15 秒一次 |
| `CUSTOM_STORY_RESTORE_GUIDE` 提示词 | **逐字移植**到 `cloudfunctions/ai/index.js` |
| 汤面+汤底+胜利条件系统提示词 | **逐字移植**（`buildPreset`） |
| 故事还原三档判定提示词 | **逐字移植**（`restore`） |
| `ai_context` 最近 40 条 | 每次提问从 `messages` 集合取最近 40 条 user/assistant |
| 回复含「故事还原正确/大致正确」→ 过关 | 同样字符串匹配 → `rooms.passed = true` → 全员弹窗 |
| 房主权限按昵称判断 | 云端按微信 openid 校验（更安全），界面显示仍按昵称 |
| 上传 JSON 题目（单题/数组，≤20MB） | 题目页「上传题目 JSON」，从微信聊天会话选文件，格式完全一致；一次可导入最多 50 道，走四阶段原子批量导入（详见「五 · 上传自定义题目」） |
| 揭晓答案 → 黄底答案框 | 同样：揭晓后题目页显示琥珀色答案卡片 |
| 每天凌晨 3 点清房 | `cleanup` 云函数 + 定时触发器（cron `0 0 3 * * * *`） |
| 群聊保留最近 100 条 | 同样保留最近 100 条 |
| 故事还原内容对其他人保密 | 同样：其他人只看到「某某提交了故事还原」 |

小改进（不影响原逻辑）：开局自动随机一题（旧版是空房等上传）；房主退出自动移交房主；同一微信号重进房间自动认回身份；**胜利条件不再展示给玩家**（旧版会显示，而胜利条件往往直接剧透答案，新版只供云端 AI 判定还原使用）。

## 四、部署步骤（保姆级，按顺序做）

> 全程大约 15 分钟。你已经有小程序 AppID，直接从第 1 步开始。

### 第 1 步：填入你的 AppID

用记事本或 VS Code 打开 `project.config.json`，把：

```json
"appid": "touristappid"
```

改成你自己的小程序 AppID（在 [mp.weixin.qq.com](https://mp.weixin.qq.com) → 开发管理 → 开发设置 里复制）。

> ⚠️ 必须用正式 AppID。测试号（touristappid）用不了云开发。

### 第 2 步：导入项目

1. 下载安装 [微信开发者工具（稳定版）](https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html)
2. 打开 → 导入项目 → 目录选择 `C:\Users\21162\Desktop\soup`
3. AppID 会自动读取第 1 步填的值 → 确定

### 第 3 步：开通云开发，拿到环境 ID

1. 点开发者工具顶部工具栏的 **「云开发」** 按钮
2. 首次会提示开通 → 同意协议 → 创建环境（环境名随便填，比如 `soup`）
   - 新用户可免费体验 6 个月（配额与 19.9 元/月基础套餐相同），到期后 19.9 元/月
3. 创建好后，在云开发控制台 **设置 → 环境 ID**，复制那串形如 `cloud1-3gabcxyz12345678` 的 ID
4. 打开 `miniprogram/config.js`，把 `envId: 'your-env-id'` 里的占位符换成你的环境 ID，保存

### 第 4 步：部署 5 个云函数

在开发者工具左侧文件树里，展开 `cloudfunctions`，对下面 5 个文件夹**逐个**操作：

> 右键文件夹 → **「上传并部署：云端安装依赖」** → 等右下角提示成功

- `room`
- `ai`
- `plaza`（第二期故事广场）
- `init`
- `cleanup`（部署时会自动带上每天凌晨 3 点的定时触发器）

然后确认 AI 函数的超时时间：云开发控制台 → 云函数 → `ai` → 配置 → **超时时间设为 60 秒**（AI 回答慢，默认值太短会中断）。

### 第 5 步：配置数据库安全规则（★ 最关键的一步）

云开发控制台 → **数据库** → 点开每个集合 → **权限设置 / 安全规则** → 选「自定义安全规则」，分别粘贴：

`rooms`、`messages`、`chat_messages` 三个集合都用这个（允许所有人读，禁止客户端写）：

```json
{
  "read": true,
  "write": false
}
```

`stories` 和 `counters` 集合用这个（**完全禁止客户端读写，汤底才保密**）：

```json
{
  "read": false,
  "write": false
}
```

> ⚠️ 如果 `stories` 设成了可读，玩家就能直接查到所有汤底，游戏就没法玩了。
> 如果集合还没出现，先做第 6 步再回来配置。

### 第 6 步：初始化数据库

左侧文件树 → 右键 `cloudfunctions/init` → **「云端测试」** → 直接点「运行测试」。

返回结果里看到 `seeded: N`（或 `skipped: N`）就成功了，N = `builtin.json` 里的题目条数（当前 2）。此时数据库里会多出 5 个集合（rooms / messages / chat_messages / stories / counters），`stories` 里有 N 道 `source: 'builtin'` 的内置题。这个函数可以重复运行，已存在的题会跳过。

### 第 7 步：确认 AI 配置（一般不用动）

旧项目的 DeepSeek 接口和 Key 已经移植到 `cloudfunctions/ai/ai-config.js`，Key 只存在云端，不会下发到玩家手机。

- 想换 Key / 接口 / 模型：改这个文件 → 重新右键 `ai` → 上传并部署
- 如果 AI 回复「模型不存在」类错误：把 `model` 改成 `'deepseek-chat'` 再部署

### 第 8 步：编译运行，拉朋友测试

1. 点工具栏 **「编译」**，模拟器里就能创建房间、和 AI 对话
2. 点 **「预览」** 生成二维码，手机微信扫码真机体验
3. 多人联机测试：把预览二维码发给朋友（朋友需先被加为体验成员：mp 后台 → 成员管理 → 体验成员），或者直接用「分享」按钮把房间卡片发给好友

## 五、玩家怎么玩

1. 首页填昵称 → **创建房间**（自动随机一道题）
2. 把顶部 6 位数字房间码发给朋友，或点「邀请」分享卡片
3. 在 **AI 推理** 页提问，AI 只答「是 / 不是 / 不重要」；卡住了点「整理线索」
4. 觉得拼出真相了 → 点「故事还原」写下完整推测 → AI 判定，猜对全员过关
5. 队友之间用 **群聊** 页讨论（AI 看不到），@昵称 会高亮
6. 房主在 **题目** 页换题、上传自己的 JSON 题库、揭晓答案

### 上传自定义题目

题目 JSON 格式与旧版**完全一致**（支持单题对象或数组批量）：

```json
{
  "surface": "汤面：玩家看到的谜题",
  "answer": "汤底：完整真相（保密）",
  "victory_condition": "胜利条件：猜出什么算过关（仅供 AI 判定，不展示给玩家）",
  "additional": "补充说明（可选，仅供 AI 参考）"
}
```

小程序里的上传方式：先把 `.json` 文件发到任意微信聊天（比如「文件传输助手」）→ 房间题目页点「上传题目 JSON」→ 从聊天会话里选中该文件。

#### 批量导入是怎么走的（一次传 10 题也没问题）

`cloudfunctions/room/index.js` 的 `uploadStories` 分成四个阶段，**要么整批成功，要么整批回滚**：

1. **全量校验**：先检查每一道题的 `surface` / `answer` / `victory_condition` 是否存在，只要有一道不合格就直接报第几道题不合格，一条都不写库（不会留下"入库了但前端看不到"的孤儿数据）。
2. **批量内容安全检测**：按题逐条送检（`secCheckBatch`），但每组 5 题**并发**送检，10 道题只需要 2 轮网络往返——既不会超时，也不会因为多道题的死亡/案件描述拼在一起被误判。
3. **分组并发写库**：每组 10 条并发写入 `stories` 集合，`source: 'upload'` + `roomCode`。
4. **一次性绑定**：所有题写完后，才把 `storyIds` / `currentStoryIndex` 一次更新到 `rooms`。前端 `listRoomStories` 按 `storyIds` 查询，所以只有第 4 步成功，玩家才看得到新题。

第 3、4 阶段任一失败，会自动删掉本批已写入的题再报错，不会污染题库。

常见报错对照：

| 报错 | 原因 |
|---|---|
| 「第 N 道题包含违规内容，本批 M 道题均未导入」 | 内容安全检测拦下了第 N 题，改掉该题的敏感表述再传 |
| 「JSON 解析失败」 | 用了单引号、最后一项多了逗号，或文件不是 UTF-8 编码 |
| 「一次最多导入 50 道题」 | 拆成多个文件分几次传 |
| 「导入超时/网络错误」 | 题量过大时偶发，重新点一次即可（回滚机制保证不会重复堆积） |

> 提示：上传的题是**临时题**（`source: 'upload'`），关房或每天凌晨 3 点的 `cleanup` 会删除；想让题永久留在题库里，就编辑 `cloudfunctions/init/builtin.json` 后重新部署 `init`。

## 六、常见问题

| 现象 | 原因与解决 |
|---|---|
| 提示「还没配置云开发环境」 | `miniprogram/config.js` 的 `envId` 还是占位符，按第 3 步填 |
| 弹窗「实时同步失败」 | 安全规则没配好，按第 5 步把 rooms/messages/chat_messages 设为 `read:true, write:false` |
| 创建房间提示「题库为空」 | 没运行 init，按第 6 步云端测试一次 |
| AI 回复 `[AI错误]API 401` | Key 无效或欠费，检查 `ai-config.js` 的 apiKey |
| AI 回复 `[AI错误]...model...` | 模型名不对，把 model 改成 `deepseek-chat` 重新部署 ai |
| AI 回复 `[AI错误]AI 接口超时` | 云函数超时太短，控制台把 ai 函数超时设为 60 秒；或 DeepSeek 当时较慢，重试即可 |
| 提问后一直「思考中」 | 看上一条；回复是通过实时推送送达的，偶尔调用超时但回复仍会出现 |
| 真机预览请求失败 | 确认用的是正式 AppID（不是测试号），且云环境已开通 |
| 朋友打不开分享卡片 | 开发阶段需要把对方加为体验成员；正式发布后所有人可玩 |
| 房间突然没了 | 每天凌晨 3 点定时清房（同旧版），或房间超过 24 小时，或房主关闭了房间 |

## 七、安全设计说明

- **Key 不下发**：DeepSeek Key 只存在云函数里，前端拿不到
- **汤底保密**：`stories` 集合禁止客户端读写；`getStory` 只在房主揭晓后才返回 answer；广场列表/详情只下发汤面
- **胜利条件保密**：`victory_condition` 只存在云端供 AI 判定故事还原，任何接口都不下发给玩家（旧版会显示，容易剧透，新版已隐藏）
- **广场编辑权限**：仅发布者本人 openid 可编辑/删除自己的故事，云端校验，改前端绕不过
- **权限校验**：房主操作（切题/上传/揭晓/关房）在云端按 openid 校验，改前端代码绕不过
- **内容安全**：聊天、提问、上传题目都过微信 `msgSecCheck`（开发阶段接口不可用时会放行并记日志，**正式上线前请确认该接口正常工作**，否则可能审核被拒）
- **防剧透**：故事还原的具体内容其他玩家看不到，只看到「某某提交了还原」
